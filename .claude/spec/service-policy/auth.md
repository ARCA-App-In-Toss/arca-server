# 인증 (auth)

## 토큰

- 세션 교환을 제외한 모든 API는 `Authorization: Bearer <토큰>` 헤더로 인증한다. 인증 scheme `Bearer`는 대소문자를 구분하지 않는다
- 토큰은 서버가 발급하는 opaque 문자열이다. refresh token과 cookie는 쓰지 않는다
- 토큰의 유효 기간은 발급 시각부터 24시간이다. 응답의 `expiresAt`이 그 시각이며, 그 시각부터 만료로 본다
- 서버는 토큰 원문을 저장하지 않는다. 원문은 발급 응답에서 한 번만 나간다

## 세션 교환

앱 시작과 세션 복구 때 앱인토스 익명 키를 내고 세션을 받는다.

- 인증 없이 호출한다. 익명 키는 요청 body에만 담는다
- 익명 키가 빈 문자열이거나 없으면 `400 INVALID_REQUEST`다. 공백만 있는 키는 형식 오류가 아니라 검증 대상이다
- 서버는 앱인토스에 익명 키를 검증한 뒤에만 세션을 발급한다
  - 앱인토스가 키를 무효로 판정하면 `401 ANONYMOUS_KEY_INVALID`다. 세션과 회원을 만들지 않는다
  - 앱인토스 검증 서버가 응답하지 않거나 오류를 내면 `503 MAINTENANCE`다(`retryAfterSeconds` 없음). 세션과 회원을 만들지 않는다
- 유효한 키에 연결된 회원이 있으면 `ACTIVE` 세션과 그 회원 profile을, 없으면 `GUEST` 세션을 받는다. 회원 연결은 `member.md`를 따른다
- 세션 교환은 회원을 만들지 않는다
- 다시 교환하면 매번 새 토큰을 발급한다. 이전 토큰은 폐기하지 않고 만료까지 유효하다
- 응답은 정책 목록을 담지 않는다. 정책 목록은 별도 조회로 받는다 (`consent.md`)
- 익명 키 원문은 저장하거나 로그에 남기지 않는다. 서버는 SHA-256 해시만 저장한다
- 세션은 mode와 관계없이 발급에 쓴 익명 키 주체(해시)에 묶인다. `ACTIVE` 세션은 그 회원에도 묶인다

## 인증 실패 판정

요청마다 아래 순서로 판정하고, 처음 걸린 조건의 오류로 응답한다.

1. `Authorization` 헤더가 없거나, `Bearer` 형식이 아니거나, 토큰이 비어 있으면 `401 SESSION_INVALID`
2. 서버가 발급한 적 없는 토큰이면 `401 SESSION_INVALID`
3. 서버가 폐기한 토큰이거나 만료된 토큰이면 `401 SESSION_RECOVERY_REQUIRED` (`recovery.kind = REESTABLISH_SESSION`). 클라이언트는 세션을 다시 교환한다
4. 엔드포인트가 허용하지 않는 세션 mode면 `403 SESSION_SCOPE_INSUFFICIENT`

- 폐기된 토큰과 모르는 토큰을 구분하려고 폐기된 세션도 지우지 않고 남긴다

## 토큰 폐기

서버는 아래 경우에 토큰을 폐기한다. 그 밖의 토큰은 만료까지 유효하다.

- 회원 가입이 성공하면 가입에 쓴 GUEST 토큰 (`member.md`)

## 세션 mode

| mode | 조건 | 회원 |
|---|---|---|
| `GUEST` | 유효한 익명 키지만 활성 회원이 없음 (처음 온 사용자, 전체 삭제 뒤 재가입 전) | 없음 |
| `ACTIVE` | 활성 회원과 연결됨 | 있음 |

- 엔드포인트마다 허용하는 mode가 정해져 있다. 허용 mode를 정하지 않은 엔드포인트는 인증 없이 호출된다 (현재는 세션 교환만 해당)
- 응답 유실 복구를 위한 별도 mode(`DELETION_RECOVERY`)와 결과 확인(ack)은 두지 않는다. 실제로 유실 문제가 관측되면 그때 보완한다
