# 답변 (answer)

## 공통

- 허용 세션 mode는 `ACTIVE`다. `GUEST` 세션은 `403 SESSION_SCOPE_INSUFFICIENT`다
- 회원 x 배포 단위(KST 날짜)당 답변은 최대 1개다
- 답변은 회원 본인만 수정, 삭제할 수 있다. 없는 답변, 지운 답변, 다른 회원의 답변은 구분하지 않고 모두 `404 ANSWER_NOT_FOUND`다
- 숫자가 아닌 답변 ID는 `400 INVALID_REQUEST`다
- 답변 원문, 질문 원문은 로그와 오류 응답에 남기지 않는다

## 본문 규칙

작성과 수정에 똑같이 적용한다.

- trim하거나 축약하지 않고 받은 그대로 저장한다
- 확장 grapheme cluster 기준 1~2,000자다. 결합 이모지(👨‍👩‍👧‍👦)는 1자, 논리적 줄바꿈(`\r\n` 포함) 1개는 1자다
- 공백만 있어도 유효하다. 빈 문자열은 0자라 거절한다
- 코드 포인트가 15,000개를 넘으면 거절한다 (결합 문자를 이어 붙인 비정상 입력 방지)
- 위반하면 `422 ANSWER_CONTENT_INVALID`이고 아무것도 바뀌지 않는다

## 작성

- 오늘은 서버가 요청을 받은 시점의 KST 날짜다. 작성 시각(`createdAt`)과 작성 날짜(`createdDateKst`)는 같은 시점에서 정한다
- 클라이언트는 오늘 조회에서 받은 배포 단위 ID, SEMA 콘텐츠 ID, 고른 질문의 ID, 본문을 보낸다. 질문 원문은 보내지 않는다 (보내면 `400 INVALID_REQUEST`)
- 요청마다 아래 순서로 판정하고, 처음 걸린 조건의 오류로 응답한다
  1. 배포 단위 ID가 서버 오늘이 아니면 `422 DATE_CHANGED` (`recovery.kind: REFRESH_TODAY`)
  2. 오늘 편성된 SEMA가 없으면 `503 SEMA_NOT_FOUND` (`semaphore.md`)
  3. SEMA 콘텐츠 ID가 현재와 다르면 `422 SEMA_REPLACED` (`REFRESH_TODAY`)
  4. 질문이 현재 SEMA의 기본, 대체 질문이 아니면 `422 SEMA_REPLACED` (`REFRESH_TODAY`)
  5. 오늘 답변이 이미 있으면 `409 ANSWER_ALREADY_EXISTS`
  6. 본문 규칙 위반이면 `422 ANSWER_CONTENT_INVALID`
- 같은 날짜에 작성 요청이 동시에 와도 UNIQUE 제약으로 하나만 저장된다. 경쟁에서 진 요청은 DB 예외로 `500 DATABASE_ERROR`다. 더블탭 같은 중복 제출은 프론트가 버튼 비활성화로 막는다
- 저장할 때 고른 질문과 그날의 SEMA를 함께 기록한다
- 성공 응답은 `201`이고 저장된 답변과 저장 후 활성 답변 수를 담는다
- 오늘 답변을 지웠다면 같은 KST 날짜 안에서 다시 작성할 수 있다

## 답변의 질문

- 답변은 답변한 질문과 SEMA를 그대로 돌려준다. 질문, SEMA는 고치지 않고(`semaphore.md`), 예비 교체 뒤에도 교체 전 SEMA가 남으므로 바뀌지 않는다
- 답변 수정은 질문과 SEMA를 바꾸지 않는다

## 수정

- 날짜, SEMA를 검사하지 않는다. 과거 날짜 답변도 수정할 수 있다
- 요청마다 아래 순서로 판정한다
  1. 답변이 없거나 본인 것이 아니면 `404 ANSWER_NOT_FOUND`
  2. 본문 규칙 위반이면 `422 ANSWER_CONTENT_INVALID`
- 오류로 끝나면 본문이 바뀌지 않는다
- 성공하면 본문을 바꾸고 마지막 수정 시각을 갱신한다. 수정됨(`isEdited`)은 마지막 수정 시각이 작성 시각과 다른지로 판정한다. 같은 본문으로 다시 수정해도 수정됨이다
- 작성 시각과 작성 날짜는 바뀌지 않는다
- 성공 응답은 `200`이고 수정된 답변과 현재 활성 답변 수를 담는다

## 삭제

- 요청 하나로 답변 하나를 지운다. 되돌리기는 없다
- 답변이 없거나(이미 삭제 포함) 본인 것이 아니면 `404 ANSWER_NOT_FOUND`
- 성공 응답은 `200`이고 삭제 후 활성 답변 수를 담는다
- 지운 뒤에는 그 답변의 수정, 삭제가 `404 ANSWER_NOT_FOUND`이고, 오늘 조회는 해당 답변이 없는 상태를 돌려준다

## 동시 수정, 삭제

- 답변에는 revision(낙관적 잠금)이 없다. 수정, 삭제는 클라이언트가 본 버전을 확인하지 않는다
- 같은 답변에 수정, 삭제가 동시에 오면(다른 기기 등) 따로 막지 않는다. 둘 다 성공할 수 있고 나중 것이 남는다. 실제 문제가 보이면 그때 보완한다

## 활성 답변 수

- 회원에게 지금 남아 있는 답변 수다. 작성하면 1 오르고 삭제하면 1 내려가며, 수정은 바꾸지 않는다
- 누적 작성 수나 첫 사용 여부가 아니다
